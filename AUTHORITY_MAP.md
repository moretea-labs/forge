# Forge semantic authority map

Candidate scope: convergence from frozen source tree `d2db510954aaccc3429d774baee1b6ae9d782e2a`, followed by exact-content validation in an isolated Forge managed worktree.

This map records **semantic authority**, not merely file ownership. A facade may translate or orchestrate calls into an authority, but must not independently reimplement admission, persistence, or lifecycle policy. Compatibility paths are acceptable only when they delegate to the canonical writer or are read/import-only.

## Candidate-specific authority fences

1. **Typed workspace placement is admission data.** `workspaceMode`, `requireWorktree`, and `directMainProhibited` are normalized by `workspace-admission.ts` before route selection. Route Policy or `force_mode=direct_control` cannot silently override explicit isolation.
2. **Requirement bootstrap policy is no longer an MCP concern.** `runtime-tools.ts` translates the request and calls `admitRequirement`; create/reuse/conflict identity semantics live in one domain authority.
3. **Repository compatibility writers delegate.** Direct Edit Work creation, prepared Work creation, Work placement materialization, missing WorkHandle repair, and retained-cancelled Work reauthorization have canonical control-plane entry points rather than transport-owned policy.
4. **Candidate self-host checks have an explicit isolated ControllerHome.** The isolated state root lives under the verification clone's `.git/forge-candidate-controller`, so it is separated from known-good A and does not appear as Candidate source/untracked evidence. Host `FORGE_CONTROLLER_*`/runtime-private state remains sanitized from generic repository child processes.
5. **Compiled Candidate manifests are closed over their executable surface.** Candidate staging reloads the immutable manifest through `release-manifest.ts`, requires every compiled runtime component identity pair, reconciles receipt/release/source identity, then validates physical regular-file/directory type, SHA-256 and execute bits. Unknown future manifest fields remain forward-compatible, but cannot substitute for the known closed component set.
6. **Browser retries are outcome-aware.** Only replay-safe observation actions on existing resources may retry after dispatch. A transient failure after a potentially mutating dispatch returns `PLUGIN_BROWSER_MUTATION_OUTCOME_UNKNOWN` rather than blindly replaying.
7. **Physical distribution copies are not authoring authorities.** Root `scripts/`, root reference configs, and root Claude templates are authoring inputs; packaged downstream copies are deterministic projections checked by `scripts/sync-generated-authority.mjs` and the `prepack` drift gate.
8. **Work verification resolves check authority from the Work-bound checkout.** `rh_work verify` resolves the WorkContract checkout before check-id classification and enumerates that checkout's registered checks. If the Work checkout cannot be resolved, verification fails as infrastructure instead of silently falling back to canonical/main. Candidate-added checks therefore share one revision-bound registry view with Context/Process verification.
