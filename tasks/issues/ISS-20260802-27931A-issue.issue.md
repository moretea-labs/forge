# 主服务不可用时仍能远程恢复

2026-08-11 restart storm incident 已 reopen：同一坏 Runtime release 在短暂 healthy 后清空 restart attempts，因而可无限重新获得 1/3。修复已由 immutable Recovery release `2dac48e5` 部署；Runtime MCP surface fence 已由 `339fe090` 部署。保留独立 Recovery 用户需求，源码继续位于 monorepo，但安装后使用自包含不可变发布、独立 launchd、独立状态、独立公网入口和独立 tunnel，不依赖主 Gateway、Daemon、active runtime 或 worktree。

## Goals

- Preserve monorepo source ownership for Supervisor and standalone Recovery.
- Install Recovery Gateway and Watchdog as self-contained immutable versioned artifacts with atomic activation.
- Keep Recovery Gateway, Recovery Watchdog and recovery tunnel as separate OS service units from Primary runtime services.
- Persist Recovery Watchdog state and prevent repeated noisy degraded loops or repeated rollback after watchdog restart.
- Probe and repair the dedicated Recovery public endpoint independently from the primary MCP endpoint.
- Remain usable when the repository checkout, Primary Gateway, Controller Daemon and active runtime are unavailable.

## Non-goals

- Do not make Recovery depend on the primary Gateway, Controller Daemon, active runtime instance, repository worktree or Bun at runtime.
- Do not let Supervisor supervise Recovery Gateway or Recovery Watchdog; launchd/systemd remains their common lower-level authority.
- Do not allow arbitrary shell execution or let Recovery mint/write primary runtime authority.
- Do not preserve or extend the old long-lived blue/green slot model for compatibility.
- Do not create a separate Recovery Git repository.

## Acceptance Criteria

- [ ] Recovery source remains under the repo-harness repository and is built from a clean canonical revision.
- [ ] Installed Recovery artifacts live under versioned immutable release directories and activate atomically.
- [ ] Recovery Gateway and Recovery Watchdog cold-start successfully without the repository worktree, primary Gateway, Controller Daemon or active runtime.
- [ ] Both Recovery services restart after abnormal exit and remain stopped after an explicit authorized unload.
- [ ] A dedicated recovery cloudflared service exposes only the Recovery endpoint and is independently repairable.
- [ ] Watchdog separately evaluates local primary state, primary public endpoint, local Recovery Gateway and public Recovery endpoint.
- [ ] Watchdog state survives restart and rollback/tunnel-repair actions remain idempotent, identity-scoped and rate-limited.
- [ ] Recovery cannot mutate primary runtime authority and exposes only bounded verify/restart/rollback/cleanup operations.
- [ ] Focused unit, smoke, launchd template, interrupted-install and tunnel-failure tests pass.
