# P0 Recovery Evidence

- Date: 2026-08-02
- Root cause: Supervisor recovery treated the managed Daemon/Gateway pair as all-or-nothing and rollback could only infer the registered previous slot. When Gateway was absent after Supervisor restart, stable ingress remained unavailable; Recovery then rejected the previous release because its evidence was not independently attested, while other registered known-good releases were never eligible targets.
- Change: Recovery now resolves the active release from either managed child, validates immutable release closure and exact manifest hash, and selects only registered evidence carrying Controller Home, config revision/hash, and writer-fencing attestation. Rollback submits a new Supervisor operation with an explicit target release path and records audit/quarantine evidence.
- Change: Supervisor rollback starts the explicit registered target when no live standby pair exists, commits rollback authority with release metadata, refreshes writer claims after commit, and tolerates a missing failed Gateway during cleanup. Supervisor activation rollback restores the generated service definition before reinstalling the service.
- Verification: `bun run check:type`; `bun test tests/runtime/standalone-recovery.test.ts tests/runtime/stable-supervisor-hardening.test.ts` (77 passed); `bun run check:runtime-architecture`.
- Runtime authority hardening: `runtime-authority.json` now binds `configRevision` and `configHash`; active/previous release identities require `instanceId`; `runtime-config.json` requires `configRevision`; readers reject missing or mismatched bindings.
- Extended verification: `bun test tests/runtime/standalone-recovery.test.ts tests/runtime/stable-supervisor-hardening.test.ts tests/runtime/stable-state-and-bootstrap.test.ts` (93 passed), typecheck, and runtime architecture check.
- Ingress now emits `x-runtime-authority-term` and `x-runtime-authority-revision` from a per-request read of the canonical authority, including degraded and recovery responses; no second active pointer was introduced.
- Runtime evidence (2026-08-02): existing installed release `183c490...` was observed after an explicit controlled restart request; Supervisor/Ingress restarted, Daemon became ready, but Gateway never reached readiness. Gateway logs show the installed release attempted `posix_spawn` of the source checkout `src/runtime/execution/process-runtime/process-runner-entry.ts` and failed with `EACCES`. The current source fix in `2ff6eda64` prefers the immutable release sibling `process-runner.js`, but proving live recovery requires installing/activating a release built from that revision.
