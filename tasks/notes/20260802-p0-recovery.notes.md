# P0 Recovery Evidence

- Date: 2026-08-02
- Root cause: Supervisor recovery treated the managed Daemon/Gateway pair as all-or-nothing and rollback could only infer the registered previous slot. When Gateway was absent after Supervisor restart, stable ingress remained unavailable; Recovery then rejected the previous release because its evidence was not independently attested, while other registered known-good releases were never eligible targets.
- Change: Recovery now resolves the active release from either managed child, validates immutable release closure and exact manifest hash, and selects only registered evidence carrying Controller Home, config revision/hash, and writer-fencing attestation. Rollback submits a new Supervisor operation with an explicit target release path and records audit/quarantine evidence.
- Change: Supervisor rollback starts the explicit registered target when no live standby pair exists, commits rollback authority with release metadata, refreshes writer claims after commit, and tolerates a missing failed Gateway during cleanup. Supervisor activation rollback restores the generated service definition before reinstalling the service.
