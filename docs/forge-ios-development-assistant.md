# Forge iOS Development Capability

Forge provides optional iOS simulator, physical-device, build, inspection, and App Store related operations through first-party adapters. Operations remain repository-scoped, permission-gated, timeout-bounded, and evidence-producing. Device or account approval remains a human interaction boundary. On a paired real iPhone, CoreDevice launch success is confirmed from valid structured JSON (not the human-readable stderr progress line), and app foreground is independently verified by a fresh screenshot before input. Structured subprocess JSON must remain parseable after secret redaction (including CoreDevice `auditToken`). Foreground-unconfirmed system navigation uses one-shot screenshot-bound `physical_device_observed_tap` or `physical_device_observed_swipe` to reach the target app; ordinary app gestures still require fresh verified target foreground. Fast physical-device tap/type requires the Controller-owned `pymobiledevice3 11.24.0` toolchain. Version `10.2.1` incorrectly numbers successive RemoteXPC requests, causing the device-side connection to close during clipboard-backed Unicode input. A managed input action waits for its own worker initialization because prewarm from a prior isolated plugin process is not persistent authority. If that toolchain is not installed, the provider must report unavailable rather than claim live product prices. Shopping price claims require a fresh observed product or checkout view and its exact package specification; search listings or historical deal pages alone are not checkout evidence.

See [Plugin management](forge-plugin-management.md), [Human Interaction Plane](architecture/CURRENT.md), and the [iOS physical-device migration baseline](architecture/decisions/20260904-ios-device-migration-baseline.md).

Ordinary physical-iPhone App operation is exposed only under `plugin_id=computer`, using the existing `physical_device_*` action schemas and CoreDevice/RemoteXPC implementation, including exact-phone authorization and screenshot-bound input. The `ios` plugin retains Xcode build, Simulator, smoke review and explicit agent-device/XCTest development capabilities. No separate iPhone Computer provider, session store or implicit retry path is introduced. The new runtime-facing action surface requires a subsequent release activation and live phone acceptance before treating shopping or medical-document outcomes as verified.
