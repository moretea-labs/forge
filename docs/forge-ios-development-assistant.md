# Forge iOS Development Capability

Forge provides optional iOS simulator, physical-device, build, inspection, and App Store related operations through first-party adapters. Operations remain repository-scoped, permission-gated, timeout-bounded, and evidence-producing. Device or account approval remains a human interaction boundary. On a paired real iPhone, CoreDevice launch success is confirmed from valid structured JSON (not the human-readable stderr progress line), and app foreground is independently verified by a fresh screenshot before input. Structured subprocess JSON must remain parseable after secret redaction (including CoreDevice `auditToken`). Foreground-unconfirmed system navigation uses one-shot screenshot-bound `physical_device_observed_tap` or `physical_device_observed_swipe` to reach the target app; ordinary app gestures still require fresh verified target foreground. Fast physical-device tap/type requires the canonical `pymobiledevice3` toolchain; a managed input action waits for its own worker initialization because prewarm from a prior isolated plugin process is not persistent authority. If that toolchain is not installed, the provider must report unavailable rather than claim live product prices. Shopping price claims require a fresh observed product or checkout view and its exact package specification; search listings or historical deal pages alone are not checkout evidence.

See [Plugin management](forge-plugin-management.md), [Human Interaction Plane](architecture/CURRENT.md), and the [iOS physical-device migration baseline](architecture/decisions/20260904-ios-device-migration-baseline.md).
