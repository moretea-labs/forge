# Forge 工作流简化项目 - 进展报告

## 项目概述

基于对 Forge 设计的深入分析，启动了一个多阶段的简化项目，旨在将 Forge 从"复杂的智能编排系统"转变为"增强的开发终端"。

## 核心问题

### 当前状态
- **代码规模**：190,000 行代码，547 个 TypeScript 文件
- **过度抽象**：Work 准备涉及 4 个状态机（WorkHandle/WorkContract/ExecutionSession/PrepareRequest）
- **使用不符**：简单的"读-改-测"循环需要复杂的 Work 生命周期管理
- **工具限制**：强制使用 `rh_context`，限制了模型自由组合工具

### 核心矛盾
**Codex/Claude 的实际工作方式**：
```bash
grep -r "pattern" src/    # 快速搜索
cat file.ts               # 读文件
npm test                  # 运行测试
git commit -am "fix"      # 提交
```

**Forge 强制的流程**：
```typescript
1. work_prepare() -> 创建 Work、WorkHandle、WorkContract、Session
2. 验证权限、检查租约、验证 checkout
3. 执行操作
4. 验证结果
5. 清理资源
```

## 解决方案：三阶段简化

### Phase 1: 消除冗余读取（✅ 已完成）

**成果**：
- PR #423：消除 5 处冗余的会话读取
- 节省 0.1-5ms/操作
- 所有测试通过，行为不变

**技术细节**：
```typescript
// 优化前：写后立即读
updateExecutionSession(...);
return { session: requireSession(ctx, args), ... };

// 优化后：直接使用返回值
const nextSession = updateExecutionSession(...);
return { session: nextSession, ... };
```

### Phase 2: 引入轻量级会话（🔄 进行中）

**Task 1 完成**：LightweightWorkSession 基础设施
- ✅ 创建轻量级会话接口和存储
- ✅ 18 个测试全部通过
- ✅ 向后兼容（opt-in 模式）

**技术创新**：
```typescript
// 轻量级会话：跳过复杂的 Work 创建
prepareLightweightSession() {
  // 1. 快速验证（无 WorkHandle）
  // 2. 记录 baseline（用于 diff）
  // 3. 最小状态持久化
  // 4. 直接绑定 session
  // 结果：~5ms vs ~50ms
}
```

**关键设计决策**：
- **Opt-in 模式**：通过 `lightweight: true` 显式启用，避免破坏现有工作流
- **保留完整 Work**：需要隔离/验证/长期追踪时仍使用完整 Work
- **最小持久化**：仅记录恢复所需的基本信息

**收益**：
- 准备时间：~50ms → ~5ms（10倍提升）
- 数据库写入：8 次 → 1-2 次
- 代码复杂度：大幅降低

**剩余任务**：
- 🔄 Task 2: 简化 reuse 路径的完整 Work 流程
- ⏳ Task 3: 延迟验证和缓存
- ⏳ Task 4: 减少 Git 调用
- ⏳ Task 5: 放开终端限制

### Phase 3: 架构重构（⏳ 计划中）

**目标**：
- 轻量级模式成为默认
- 完整 Work 降级为"需要隔离时"的可选机制
- 删除不必要的抽象层

## 架构原则

通过这个项目确立的核心原则：

1. **Forge 是工具箱，不是编排器**
   - 提供强大的能力，不强制工作流
   - 让模型自由组合工具

2. **复杂度分层**
   - L0（90%）：直接终端操作
   - L1：带追踪的会话
   - L2：完整隔离的 Work

3. **默认简单，可选复杂**
   - 简单场景零成本
   - 复杂场景完整能力

4. **保留企业级优势**
   - 可恢复性
   - 并发安全
   - 审计能力

## 总结

这个项目代表了 Forge 架构演进的关键转折点：

**从**：复杂的编排系统，试图控制一切
**到**：强大的工具箱，赋能模型自由工作

Phase 1 已成功完成，Phase 2 基础就绪，正在按计划推进。预计在 2-3 周内完成 Phase 2，1-2 月内完成 Phase 3。

这将使 Forge 更快、更简单、更符合实际使用模式，同时保留其企业级能力。
