# Forge 1.6 Architecture Snapshot

Status: **Version Snapshot — Not Runtime Authority**

This is the release-family architecture record for Forge 1.6. The live architecture contract is [`../CURRENT.md`](../CURRENT.md).

## Architecture shape

```text
ChatGPT / semantic controller
  -> stable 19-tool MCP facade
     -> Context Engine / repository primitives / plugin dispatcher
     -> Ephemeral or Lightweight local execution
     -> optional Work + Durable Process for continuity
     -> immutable Canonical Runtime release + standalone recovery
```

## Key contracts

- Default MCP surface: 19 stable tools; `core` and `advanced` are the same bounded default surface.
- Explicit `full` profile preserves historical compatibility definitions but is not used to construct the default schema.
- `rh_context` supports progressive raw-source retrieval with exact-known-path reservation, symbol materialization, session caching, CodeGraph hints and changed-file overlays.
- Ordinary local command execution is Direct/Lightweight by default after command/effect policy admission.
- Work is selected for continuity, scheduling, external effects, independent deliverables, recoverability or multi-controller coordination—not predicted file/line complexity.
- Runtime availability/release recovery is separated from ordinary command recovery semantics.
- Git/worktree, Edit Session, validation evidence, optional Work and optional durable Process each own one concern; compatibility projections are not current mutable authorities.
- Canonical Runtime activates one immutable whole release and retains the previous release for rollback.

## 1.6 simplification work

The 1.6 line introduced the quality-first executable-harness direction, removed unreachable Local Bridge execution code, detached the stable Controller schema from legacy full-profile definitions, and added an internal TypeScript Language Service navigation prototype for compiler-backed references/definitions/implementations without a new dependency or durable index.

## Known compatibility boundaries

- `toolset=full` remains available for legacy consumers.
- Some legacy Issue/Task/Job and Runtime modules remain for persisted-state or compatibility reads.
- Several large modules still need responsibility-based decomposition.
- TypeScript navigation remains internal until broader repository/project-config behavior is proven.
