# Forge 1.7 Architecture Snapshot

This is the release-family architecture record for Forge 1.7. The live architecture contract is [`../CURRENT.md`](../CURRENT.md); this file is historical release evidence and must not become parallel runtime authority.

## Controller and execution model

- ChatGPT remains the sole semantic controller. Forge supplies deterministic repository, Work/Plan, Process, Schedule, provider, evidence, recovery, and release mechanisms.
- Direct/Ephemeral execution remains the default for bounded understood work. Durable Work/Plan state is reserved for continuity, isolation, scheduling, recovery, independent delivery, external effects, or real dependency decomposition.
- Work, Plan, Schedule, Handoff, Runtime, and Git are the existing durable authorities; Forge 1.7 does not add a second semantic scheduler, agent database, or completion engine.

## Persistent Autonomous Continuation

- Schedule wake resolves an existing durable Work and reuses its bound ChatGPT conversation; a new Controller round reconstructs authority from Forge state rather than chat memory.
- Round disposition is explicit (`wait`, `continue_immediately`, `wait_for_user`, or `goal_complete`). Forge-owned ChatGPT tabs settle only after the round disposition/release boundary; immediate continuation is fenced against duplicate prompt/Work creation.
- Local/remote effect Work is distinct from repository-change Work, so runtime/schedule effects can be durably verified and finalized without manufacturing a Git diff.
- Retryable readiness failures use bounded backoff while user-action/security boundaries stay fail-closed. Stable release acceptance requires real timer-origin continuation evidence, not schedule configuration alone.

## Browser Runtime V3

- Controller Home BrowserSession is the sole durable browser-session authority. Stable provider/resource target identity is distinct from mutable URL/title.
- Common native/DOM operations are background-safe when capability permits; user-owned tabs are preserved. Physical foreground input is an explicit last-resort provider and still requires independent postcondition verification.
- Native replacement waits for the exact replacement tab to settle to HTTP(S), rejects transitional `about:*` state as success, preserves strict concrete-resource URL validation, and authorizes cross-origin navigation against the destination origin.
- Transport, Apple Events, Accessibility, Desktop Operator, or CGEvent success alone is not factual completion; postconditions remain authoritative, and unknown non-idempotent outcomes are never blindly replayed.

## Typed capabilities and global provider profiles

- The ChatGPT facade remains stable while typed domain capability discovery can rank relevant plugin actions from natural intent. Discovery is read-only; `plugin_action_execute` remains the plugin execution authority.
- Controller-global plugin profiles provide reusable provider configuration with repository overlays/restrictions. App Store Connect configuration carries credential references rather than private-key contents.
- iOS build automation supports simulator and explicit physical-device destinations plus opt-in provisioning updates using file-backed App Store Connect authentication references, with redacted evidence.

## Runtime, recovery, and release boundary

- Canonical Runtime is activated as one immutable compatible release. Independent Recovery owns restart/rollback and verifies Runtime, Gateway, MCP, Scheduler, and release identity after activation.
- Source and Runtime coherence remain explicit; advancing source does not silently mutate a pinned Runtime. Release/rollback scope is the complete compatible Runtime rather than individual components.
- Finalization, target advancement, verification receipts, process/session identity, and lifecycle cleanup remain fenced so unrelated branch/source changes are not attributed to the wrong Work.

## 1.7 release acceptance

- `package:check:main` and `package:check:release` must pass on the exact candidate.
- Persistent Autonomous Continuation must be demonstrated with real timer-origin Work/conversation reuse and a stabilization-only Continuous Evolution Supervisor soak before stable publication.
- The immutable `v1.7.0` Git tag, npm `latest` package, published tarball evidence, and active Canonical Runtime must resolve to the accepted release candidate.
