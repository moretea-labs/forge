## Workflow Orchestration

- Read the tracked GitHub Issue/Project, current source, Git status, and relevant runtime facts before selecting the workflow.
- The model owns design, implementation, verification, review, and completion decisions; Forge persists runtime facts and receipts.
- Record durable product/architecture decisions and acceptance in the Issue/Project; keep task-local research in tasks/notes/ only when useful.
- Delegate only when useful and isolate only overlapping source/resource scopes.
- Across conversations or checkouts, reload exact Git revisions, diffs, Issue/Project state, and real receipts.
- Use proportionate existing checks and review the exact changes. Do not impose repo-local plan/spec/research/review/state files as completion gates.
